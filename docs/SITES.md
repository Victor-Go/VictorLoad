# 各站点原理与说明

[English](SITES.en.md) · [返回 README](../README.zh-CN.md)

## YouTube

YouTube 通过 PO Token、签名、SABR 等机制限制视频流地址。VictorLoad 会先尝试播放器接口，拿不到直链时，改为**记录播放器加载的媒体分片**，再合成文件。能否保存取决于播放器使用的媒体格式，也受下方列出的限制影响。

1. 打开视频并播放几秒。卡片上的画质下拉框会随缓冲逐渐填满，背景色就是进度（`1080p · 42%`）。
2. **缓冲完整**：按钮是「下载」，直接保存。
3. **没缓冲完整**：按钮是「自动下载」。扩展会依次跳到每个缺口（静音 16 倍速，期间锁定画质），等播放器加载完再保存；点「取消」可中止。补不上的缺口会询问你是否仍然保存已有部分。

说明：

- 进度按**位置**统计，不只是时长相加：你在播放器里拖来拖去、中间留下空洞，也会被识别出来并列出（鼠标悬停在下拉框上可以看到位置）。
- 设置里的「YouTube 优先 H.264」（默认开）让播放器使用 H.264 + AAC，音视频就能合成**一个标准 MP4**（最高 1080p）。关掉则可以用 VP9 / AV1（例如你在播放器里选了 4K），但音频和视频会保存成两个文件。
- 想要别的清晰度：先在播放器里选好，再缓冲。
- 文件由页面保存，进入浏览器默认的下载目录（不会进 `VictorLoad/<站点>/` 子目录）。
- 缓冲数据放在内存里（上限约 1.5 GB）；H.264 + AAC 会保存为标准 MP4（`ftyp` + `moov` + `mdat`）。
- 安装或更新扩展后，请**刷新 YouTube 页面**，页面脚本才会重新注入。

## X（推特）

- 读取页面自己的接口响应，找出推文视频的每一档 mp4，每档一项，GIF 也包括在内。
- 视频只在对应推文还在页面里时显示：滚走了就会从列表里消失，和其他实时内容一样。
- 图片按 `name=orig` 请求原图尺寸。X 上只有推文里的图片算作**主要**图片，头像、横幅、表情不算。

## B 站

- 读取公开的播放地址数据（和网页播放器用的相同），为每一档清晰度拿到 **mp4** 直链，每档一项。
- 给 B 站的媒体域名补上 `Referer: https://www.bilibili.com/`（declarativeNetRequest），因为它的 CDN 会拒绝没有这个头的请求。
- 能看到哪些清晰度取决于你的账号：在同一个浏览器里登录 bilibili.com 可以看到更多。B 站只以音视频分离的流提供的清晰度（例如 4K / HDR）不在列表里。

## 其他网站

- **HLS（`.m3u8`）**：页面加载播放列表时就会被发现。主列表会拆成各档分辨率。分片在 offscreen 文档里下载并合并（支持 AES-128 加密和 fMP4 的 init 段），输出 `.ts` / `.mp4`。
- **MP4 / WebM**：通过页面里的 `<video>`（`<source size=…>` 可给出分辨率选择）和网络响应发现。
- **图片**：`<img>`、`srcset`（取最大的）、缩略图所链接的大图、内联 CSS 背景图。只在网络流量里出现的大图也会列出。

## 「主要」是怎么判定的

| 内容 | 规则（按这个顺序） |
| --- | --- |
| 图片 | 你在这个网站上选过的标签结构 → 站点规则(X)→ 最小宽、高和体积 → 不在 `nav` / `header` / `footer` 里 → 与主要图片同类标签结构的图片一并提升 |
| 视频 | 你选过的标签结构 → 站点解析（一律主要）→ 最小分辨率、时长和体积 |

所有阈值都在设置里。

## 文件名

设置 → **文件名格式**。`{tab}` 是浏览器里该标签页显示的标题，`{name}` 是内容本身的名字（YouTube / X / B 站上是视频标题，其他地方是文件名），`{duration}` 形如 `5m32s`，`{resolution}` 形如 `1080p`（图片是 `1920x1080`）。同名文件会自动加序号。

## 限制

- 带 DRM（Widevine 等）的视频无法下载；`SAMPLE-AES` 加密的 HLS 不支持。
- HLS 主清单引用独立音轨时会明确提示暂不支持，并阻止下载，避免保存缺少声音的视频。
- 部分网站会校验媒体请求的 `Referer` / `Origin`，会返回 403。
